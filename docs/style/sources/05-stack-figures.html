窗口切分与 137 个重复行

每靶点恰好 400 个细胞，几乎不可能被窗口整除。
尾组不足时源码用 test_indices[:need] 从头补齐——
这是既定行为，不是 bug；后果必须自己处理。
决定切分的四行源码
inference.py · get_incontext_prediction
ratio = prompt_ratio + context_ratio # 默认 0.25 + 0.4 = 0.65 n_test = int(n_cells * (1 - ratio)) # 查询侧 35% n_base = n_cells - n_test
论文和源码在这里不一致。论文正文说提示条件占 25%；源码里决定比例的是两者之和（0.65）。照论文理解会把查询侧算多一倍（35% vs 25%）。
另一个按源码读的行为：base 池用尽会取模回绕，复用提示细胞。提示/查询比例随 context_ratio 可调，K 是运行时窗口，不是结构约束。
