VC2026 第 03 课 · 输出合同

模型吐出的不是计数，而且填不回去

这一步不需要 GPU，本机可跑；也是本课最容易翻车的一处。提交合同要求非负整数原始计数。
① 模型输出
state tx infer 在基因空间给出浮点，并裁剪到 [0,14]。
z_ig = log1p(CP10K)
→
② 空白格
没有任何官方步骤把这里的浮点还原成原始计数。
❓
→
③ 提交要求
每 context × target 400 行非负整数，基因轴顺序与 gene_names.csv 完全一致。
Y_ig ∈ ℤ, Y_ig ≥ 0
为什么 round(expm1(z)) 不对
z_ig = log(1 + 10000 · x_ig / L_i)
归一化把每个细胞的深度 L_i 除掉了。L_i 一旦丢失，expm1 只能还给你「10,000 尺度下的相对表达」，不是「这个细胞实际测到多少 UMI」。产出的数字看起来像计数，但不是任何东西的计数。
正确的两层分解
p_ig = r_ig / Σ_g r_ig ← 组成
L_i ← 同背景 NTC 深度分布
Y_i ~ Multinomial(L_i, p_i)
先定组成、再定深度，然后一次多项式抽样：保证非负整数，且行和精确等于 L_i。第 ④ 步用 NTC 深度是工程选择不是生物学定律，需做消融。
① 采样背景细胞从 NTC 分层抽样
② 预测全基因 rate上游出问题，下游修不了
③ 归一成组成先检查总和 > 0
④ 采样深度 L_i从 NTC 总计数分布取
⑤ 生成整数Multinomial 采样
⑥ 比较分布零比例、均值方差再评分
采样器不能修复错的 rate400 次重复同一个均值只会给你 400 行近似副本 —— vcc prep 会照常通过，因为它只检查格式、不检查差异。

先测出 t_step，再决定租多少卡

固定 10,000 个 optimizer step 的敏感性表。表中数字是手算，不是实跑 —— 本机没装成 arc-state。
实测每更新耗时单 run+30% 预留6 个 run
0.25 s0.69 h0.90 h5.42 GPU-h
1 s2.78 h3.61 h21.67 GPU-h
3 s8.33 h10.83 h65.00 GPU-h
10 s27.78 h36.11 h216.67 GPU-h
t_step 从 0.25 s 变到 10 s，预算差 40 倍。所以「微调大概要十小时」在测出 t_step 之前没有任何依据。

3

4
用加载报告当硬门
主干继承比例对不上，后面的钱一分都不该花
5
用实测 t_step 代进公式
反着读这张表，才得到真正需要的 GPU-h
把它反过来读打算花 60 GPU-h ÷ 6 个 run = 10 GPU-h/run，留 30% 余量 ⇒ 单 run 3.61 h ⇒ 10,000 步每步必须 ≤ 1.0 s。所以 60 GPU-h 够不够，等价于「你的 t_step 是多少」。
