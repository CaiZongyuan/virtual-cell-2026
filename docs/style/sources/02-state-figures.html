VC2026 第 02 课 · 张量契约

一次 forward：S 这一维从头到尾都不被压掉

维数取官方源码默认配置（hidden_dim=768、全基因输出）。已发布权重是另一套（328 / set 64 / 2,000），两套不可混用。
输入
X_ctrlB × S × 18,533
Z_pertB × S × D_pert
靶点向量在集合内共享同一份：一次扰动是施加在整群上的条件。
→
三个编码器 · 逐元素相加
HB × S × 768
相加而非拼接：三个信息源共享同一批坐标。
→
8 层双向集合 Transformer
残差流B × S × 768
注意力内部12 heads × 64 = 768
双向、无位置编码、无 token 词表 → 对细胞顺序置换等变。注意力学的是细胞与细胞的关系。
→
残差加回 · 投影 · ReLU
输出B × S × 18,533
末端实际调用 ReLU，不是配置里写的 softplus。输出仍是 log1p 空间的浮点，不是计数。
S 的三个值
已发布权重训练S = 64
源码默认S = 512
本赛每靶点要求S = 400
权重形状与 S 无关（没有位置编码），所以这不是「能不能加载」的问题，而是「行为会不会变」——论文报告集合大小会影响验证损失 [P1]。
S 从不被压掉 这就是「集合到集合」在张量层面的全部含义：进去 S 个细胞，出来 S 个细胞，中间每一层都同时看着这 S 个。
对照：伪批量做法 先对 S 取平均 → B × 18,533 → 细胞间异质性在第一步就丢了。论文消融里，平均池化版与集合大小为 1 的版本都明显更差 [P1]。
两套配置本图为源码默认的全基因路径。引用任何一个数字时必须说明是哪一套——「State 是 328 宽」这类无主语句子一定是错的。
VC2026 第 02 课 · 训练目标

能量距离的三项：一边拉近，一边撑开

本图画的是标准 Energy 距离定义的几何含义，不是官方实现的逐行复刻。官方配置项为 loss=energy。
D² = 2·E‖p−q‖ − E‖p−p′‖ − E‖q−q′‖
三个方向相反的力，作用在预测集合 P 与真实集合 Q 上。
1
+ 2·E‖p − q‖
两团云要靠近。降低它就是降低损失。
2
− E‖p − p′‖
预测这团云要自己散开。负号 = 奖励散开，这是不塌缩的唯一来源。
3
− E‖q − q′‖
只含真实数据，不含模型输出，求导后消失。训练中它不起作用。
如果预测塌缩成一点
E‖p − p′‖ = 0
第 ② 项这份奖励拿不到
损失被抬高
梯度把预测推开
所以它在结构上就不会退化成「输出一个均值」——不是靠调权重压住的，是那个负号把这条路堵死的。
一维手算对照
真值 Q = {0, 2}；P₁ = {0, 2} 分布正确，P₂ = {1, 1} 塌缩到均值。
判据P₁P₂选谁
MSE · 行序凑巧对齐01 P₁ ✔
MSE · 行序被打乱41 P₂ ✘
D² · 任意行序01 P₁ ✔
同一份预测、同一个真值，换个排列 MSE 就换答案。这不是算错，是它依赖了数据里不存在的前提。
它不保证什么能保证两群像、不塌缩；不保证单细胞层面「哪个对哪个」，不直接优化单个基因的方向与幅度。计数生成必须另做并单独审计。
