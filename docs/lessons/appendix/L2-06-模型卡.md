## 0. 怎么用这份文档

三个路线，六张卡。每张卡字段固定，读完能回答同一组问题：

| 卡 | 路线 | 工作 | 一句话 |
|---|---|---|---|
| 卡 1 | 分解式 | perturbation-decomposition | 把响应拆成可迁移分量，用线性模型打 |
| 卡 2 | 分解式 | AdaPert | 稀疏靶点子图 + 抗塌缩损失 |
| 卡 3 | 分解式 | C3TL | 扰动编码与背景编码分离后组合 |
| 卡 4 | 生成式 | X-Cell | 扩散语言模型 + 多模态先验 |
| 卡 5 | 生成式 | Lingshu-Cell | 掩码离散扩散直接生成转录组 |
| 卡 6 | 世界模型 | AlphaCell | 条件流匹配做连续状态转移 |

**三条路线与 B0–B3 的关系**（同一套分量口径，见 [第 06 课](../06-其余路线全景.md) §4.3）：

$$
\Delta_{c,t,g} = \underbrace{\overline{\Delta}_{t,g}}_{\text{共享分量}} + \underbrace{\Gamma_{c,t,g}}_{\text{背景特异分量（交互）}} + \varepsilon
$$

- **分解式路线**：显式地把 $\overline{\Delta}$ 和 $\Gamma$ 分开建模，$\Gamma$ 用低秩或稀疏结构。**与 B1–B3 是同一族**，只是分量更多、先验更强。
- **生成式路线**：不显式分解，直接学 $P(x \mid c, t)$。$\overline{\Delta}$ 与 $\Gamma$ 都隐含在生成分布里，**无法单独归因**。
- **世界模型路线**：把 $P(x \mid c, t)$ 扩展成 $P(x_{t+\Delta} \mid x_t, c, \text{intervention})$，多了时间轴。本赛是**单步终点预测**，多出来的那一维用不上。

**这三条路线在证据强度上不齐。** 卡 1 有可跑的官方仓库（含预计算预测结果），卡 4 只有论文与一个占位模型页，卡 6 两者都没有。**卡片里「可执行程度」一栏必须逐张看，不能因为都写着「采用为……证据」就当成同等可用。**

### 0.1 六张卡沿用同一套字段：L2 模型深潜的 8 步

本附录不占课时，但**卡片本身沿用 [README](../README.md) §4.2 的 L2 模型深潜 8 步**，这样任何一张卡都能和 [第 02 课](../02-State模型拆解.md)、[第 05 课](../05-Stack推理时把无标签细胞当示例.md)、[第 06 课](../06-其余路线全景.md) 放在同一张表里读。字段与槽位的对应关系：

| L2 深潜槽位 | 在卡片里的行名 | 读者要拿到的东西 |
|---|---|---|
| 1. **它赌什么** | 「它赌什么」 | 这句话必须能回指 [第 06 课](../06-其余路线全景.md) §1.3 的五种赌注之一 |
| 2. **输入输出契约** | 「输入输出形态」+「适配缺口」第 1–3 条 | 输入是什么张量/文件，输出的基因数与空间是什么 |
| 3. **架构** | 「关键设计」 | 一层到两层粒度，不抄论文图 |
| 4. **训练目标** | 「关键设计」的损失/目标那一句 | 目标函数在惩罚什么；**若无损失（如卡 1 的 ANOVA）要写明** |
| 5. **数据** | 「训练数据与暴露」 | 数据规模、背景数、**以及留出的是扰动还是背景** |
| 6. **官方代码怎么跑** | 「成本」+ §1 的「有官方代码吗」列 | 有代码吗、有权重吗、**跑得起来吗** |
| 7. **适配缺口** | 「适配缺口」 | 逐条写清本赛条件下**能不能满足**，不是「差多少」 |
| 8. **诊断题** | §2 三道题 | 至少一道能判定对错 |

**两个槽位在本附录里必须比正文课更严**：

- **第 5 槽「数据」要额外写清留出方式。** 正文课的模型大多在同一背景内留出扰动；本附录的六张卡里，卡 5 的 H1 实验就是「同一背景 + 150 个监督扰动」，而本赛要的是**留出整个背景**。**这两种留出不写清，卡片就会误导人。**
- **第 6 槽「官方代码怎么跑」要区分「有仓库」与「有实现」。** 卡 3 有 MIT 仓库但只有 README、LICENSE 和 `.gitignore`；卡 4 有 MODEL_CARD 但明写 `weights and inference code coming soon`。**这两种情况在「有没有代码」这个二值判断里都会显示为「有」，是错的。** §1 的对照表用四列（代码/权重/真值/面板）而不是一列，就是为了修掉这个误读。

## 卡 1｜perturbation-decomposition（分解式）

| 字段 | 内容 | 证据 |
|---|---|---|
| **它赌什么** | 赌响应可以拆成几个**可分别估计**的分量，且共享分量低维、残差高维 | 回指 [第 06 课](../06-其余路线全景.md) §1.3 的「效应迁移」赌注 |
| **输入输出形态** | 输入：伪批量 $\Delta$ 矩阵 + DepMap 共必需性向量；输出：各分量与预测的 $\Delta$ | `[S1]` 仓库 `benchmarks/`、`models/` |
| **关键设计** | 四分量 ANOVA：`delta = mu + alpha_c + beta_p + gamma_{c,p}`；再用 Ridge/MLP 把 DepMap 向量对齐到响应空间 | `[S1]` `decomposition/anova.py:3,24` |
| **训练数据与暴露** | Replogle–Nadig 四个细胞系（K562/RPE1/HepG2/Jurkat）伪批量；2,000 HVG | `[P1]` §摘要；`[S1]` README |
| **成本** | **可跑**：`data/` 已含处理好的伪批量 + DepMap 嵌入（约 90 MB）；`results/` 含全部预计算预测（约 150 MB）；从零跑一个细胞系的基线约 10 分钟 **CPU** | `[S1]` README「Quick start」 |
| **天花板判据** | 共享模板是低维的、目标与背景特异残差更高维；DepMap-aligned Ridge/MLP 在多留出设置中**匹配或超过更复杂模型** | `[P1]` |
| **与本赛的适配缺口** | 见下 | |
| **证据等级** | `[S1]` 源码 + `[P1]` 预印本（**未同行评议**）；仓库**未声明 license** | |

**适配缺口（本赛视角）**

1. **没有单细胞计数生成。** 主要实验是**伪批量终点**，不产出比赛要的 400 个原始计数细胞。要补 [第 03 课](../03-State上手.md)。
2. **零样本恢复不了 $\gamma$。** `[P1]` 作者明确发现纯零样本方法**不能恢复 `cell-line × perturbation` 交互**，只有加入目标背景 30% 扰动后才改善。**本赛 D/E/F 没有任何目标背景扰动真值**——这条正好卡死。
3. **基因数不足。** 2,000 HVG，不是 18,533 全基因。
4. **它验证的是「Ridge/MLP 能不能替代大模型」，不是「VC2026 六指标能不能提高」。** 两者不能互换。

**这张卡对本项目的实际用途**：把 `beta_p` 与 `gamma_{c,p}` 的方差比做成**靶点分档判据**——这正是 [第 06 课](../06-其余路线全景.md) §4.3 的 $\text{beta\_frac}$ 与本课 §1 口径的来源。**它是一个诊断工具，不是一个提交候选。**

## 卡 2｜AdaPert（分解式）

| 字段 | 内容 | 证据 |
|---|---|---|
| **它赌什么** | 赌「哪些基因该响应」可以由**外部先验图**给出，因此不需要端到端学习整张交互矩阵 | 回指「效应迁移 + 先验注入」 |
| **输入输出形态** | 输入：目标背景的**对照细胞** + 连续靶基因先验；输出：$3{,}352/5{,}000$ HVG 的 `log1p` 表达 | `[P2]` |
| **关键设计** | 从 STRING 蛋白互作图为每个靶基因选**稀疏、扰动特异的子图**；三个目标：全局重建 + 非 DEG 稳健惩罚 + DEG 响应对齐。**第三个目标直接针对「均值塌缩」** | `[P2]` |
| **训练数据与暴露** | K562、RPE1、HepG2、Jurkat 四个 CRISPRi 数据集；另有「三个细胞系训练、整个 K562 留出」的跨细胞系实验 | `[P2]` |
| **成本** | **未披露。** 论文没有给参数量、硬件或训练时长 | `[P2]` 缺口 |
| **天花板判据** | 在 K562 跨细胞系 Systema 评估中，perturbation-reference 分数**高于 State**；但在另一组汇总指标中**并未全面胜出**，且直接跨细胞系 Perturb Mean 在 Pearson-delta 上仍更强 | `[P2]` |
| **与本赛的适配缺口** | 见下 | |
| **证据等级** | `[P2]` ICML 2026 论文；**无可明确识别的官方代码仓库** | |

**适配缺口（本赛视角）**

1. **输入形态最接近本赛**——这是本课六张卡里**唯一同时接收「目标背景对照细胞 + 靶基因先验」**的。这一点值得单独记：它证明了「NTC + 靶点先验 → 响应」这个接口**在文献中是成立的**。
2. **它的三项指标（`reach`、`nmae`、方向 fidelity）与比赛的六项指标有对应关系**，但不是同一套实现。**不能把论文数字换算成 `avg_score`。**
3. **只在 `log1p` 空间评估，没有原始计数。** 同上，要补计数生成器。
4. **稀疏响应门是组件级的可复用资产**，不是端到端方案。本课的建议是**复用「响应概率头 + 抗塌缩损失」这两个想法**，而不是复现模型。

**这张卡对本项目的实际用途**：**「响应概率头」是 B3 低秩交互项之外的一个独立候选**——它不预测幅度，先预测「这个基因会不会动」。若 [第 04 课](../04-你怎么知道改进是真的.md) 的地板表明幅度预测不可判定，方向预测仍可能可判定。**这是一个可以被证伪的小实验，成本低。**

## 卡 3｜C3TL（分解式）

| 字段 | 内容 | 证据 |
|---|---|---|
| **它赌什么** | 赌「扰动效应」和「背景属性」可以各自从**别的背景/别的扰动**里聚合出来，再在低维空间组合 | 回指「效应迁移」+「背景表示」 |
| **输入输出形态** | 输入：扰动表示 + 背景表示；输出：新的「背景—扰动」组合的伪批量响应 | `[P3]` |
| **关键设计** | 同一扰动跨多个背景的伪批量效应 → 聚合为**扰动表示**；同一背景的多种已测扰动 → 聚合为**背景表示**；轻量解码器组合 | `[P3]` |
| **训练数据与暴露** | Replogle、Parse、Tahoe 的 2,000 HVG 伪批量任务 | `[P3]` |
| **成本** | **训练 epoch 约快 30 倍、显存约 2.1 GB** | `[P3]` 作者自报 |
| **天花板判据** | 与 State 相近或更好 | `[P3]` 作者自报 |
| **与本赛的适配缺口** | **最致命的一张。** 见下 | |
| **证据等级** | `[P3]` arXiv 预印本；作者仓库**只有 README、LICENSE 和 `.gitignore`，没有实现代码**；参数量与训练墙钟时间未披露 | |

**适配缺口（本赛视角）**

1. **它的「背景表示」是用目标背景里已测扰动聚合出来的。** `[P3]` 主实验把目标背景 **8% 真实扰动用于训练、2% 用于验证**，余下 90% 才用于测试；连数据稀缺实验也至少用 **1%** 的目标背景干预结果。**本赛 D/E/F 对目标背景只给 NTC，一格扰动真值都没有**——按原方法**构造不出背景编码**。
2. **不能把它的「与 State 相近」当成零样本证据。** 它的测试集是「同一背景内留出的扰动」，不是「留出的背景」。
3. **仓库是空的。** 想复用只能从论文复述实现，成本高于直接写一个 B3。

**这张卡对本项目的实际用途**：**保留它的分解结构，不保留它的数字。** 它和卡 1 一起支持「把响应拆成可迁移分量 + 背景分量」这个做法本身；但**它的成功条件恰好是本赛不具备的那个条件**。这张卡最值得记住的其实是它的**反例价值**——「有 1% 目标背景扰动」和「有 0%」之间是一条断崖，不是一条斜坡。

## 卡 4｜X-Cell（生成式）

| 字段 | 内容 | 证据 |
|---|---|---|
| **它赌什么** | 赌**数据量与模型规模**能像 LLM 一样把跨背景零样本泛化刷出来，且多模态先验可以替代手工设计的分量分解 | 回指「规模化」赌注 |
| **输入输出形态** | 输入：`control_cells.h5ad` + 扰动名；输出：预测的表达 | `[S2]` MODEL_CARD 用法段 |
| **关键设计** | **集合级扩散 Transformer**（建模细胞集合，不是单细胞）；掩码扩散，推理时 **4 步 coarse-to-fine**；**Flamingo 式 cross-attention** 注入六种先验（ESM-2、STRING、GenePT、DepMap、JUMP-Cell Painting、scGPT）；输出嵌入 tied + PaLM 式 $1/\sqrt{d}$ 缩放 | `[S2]` MODEL_CARD「Architecture」 |
| **训练数据与暴露** | **X-Atlas/Pisces：25.6M 扰动单细胞 × 7 个 CRISPRi Perturb-seq screen**（HCT116/HEK293T/HepG2/iPSC/Jurkat Resting/Jurkat Active/iPSC Multi-Diff） | `[S2]` MODEL_CARD 训练数据表 |
| **成本** | 公开的只有 **X-Cell Mini = 55M 参数**，自述「单 GPU 可跑」；**权重与推理代码尚未发布** | `[S2]` MODEL_CARD「Status」 |
| **天花板判据** | 自述四项：留出 iPSC 上 Pearson delta 比次优方法高 **5 倍**；零样本 T 细胞失活（预测出 CD3 复合物成员与 LRBA/APPL2）；**训练损失呈 LLM 级缩放律 $L(N) \sim N^{-0.32}$（$R^2=0.96$）**；零样本泛化到黑素细胞祖细胞与原代人 CD4+ T 细胞 | `[S2]` 作者自述，**本课未复现** |
| **与本赛的适配缺口** | 见下 | |
| **证据等级** | `[S2]` 固定 commit 官方 MODEL_CARD；`[P4]` bioRxiv 预印本。**所有亮眼数字均为作者自报** | |

**适配缺口（本赛视角）**

1. **权重与代码都没发布。** `[S2]` MODEL_CARD 顶部明写 `Status: Model weights and inference code coming soon.`；`docs/references/REPOS.md` 登记的 `x-cell` 仓库（commit `7195c647b8`）只有工程骨架，Hugging Face 页只有 README、概览图与属性文件。**所以它现在连「小批推理」都做不了，只能作为论文证据读。**
2. **许可为 CC BY-NC-SA 4.0。** `[S2]` MODEL_CARD front-matter。比 MIT 更严：**非商业** + **相同方式共享**。用于比赛要注意这条与比赛规则的关系，不要默认「开源即可用」。
3. **基因数**：25.6M 细胞的训练语料是 X-Atlas/Pisces，**与比赛面板不同**，交叉使用要先对齐。
4. **它没有单细胞原始计数的合同说明。** 生成式模型能不能输出整数 UMI，MODEL_CARD 没说。
5. **$N^{-0.32}$ 缩放律的含义要收窄读。** 它说的是**训练损失**随参数量的下降，**不等于**比赛六指标随参数量下降，也不等于「再多数据就能赢 State」。

**这张卡对本项目的实际用途**：**两条可借鉴的设计，与能否跑模型无关。**
- **集合级建模**：X-Cell 与 State（[L2-01](../02-State模型拆解.md)）都选择在**细胞集合**上算概率/损失，而不是逐细胞。这是本任务形态（给一群 NTC，要一群扰动细胞）的自然选择，值得作为架构约束继承。
- **零样本泛化到 T 细胞**那一项，其 Cell 背景（Jurkat 静息/激活）**与本赛背景之一同类**——但 `[S2]` 没给可比数字，**不能据此推断 X-Cell 在本赛上的表现**。

| **成本** | 三个 **85M** checkpoint 公开：`parse_pbmc_uncond_85M`、`vcc_perturbation_85M`、`parse_cytokine_85M`；附 ESM2 基因嵌入与 clue 文件。**需 CUDA + C++ 编译器**（flash-attention / fused kernel） | `[S3]` README |
| **天花板判据** | `[S3]` 本地材料报告其在 VCC H1 基准上的表现；**本课未复现** | `[R1]` |
| **与本赛的适配缺口** | 见下 | |
| **证据等级** | `[S3]` 固定 commit 官方仓库与配置（commit `0cbde2feb6`，MIT）；`[P5]` arXiv v1；`[R1]` 机器转换本地材料 | |

**适配缺口（本赛视角）**

1. **H1 实验不能冒充匿名背景结果。** `[P5]` H1 用**同一背景的 150 个监督扰动**，词表 **18,080 genes**；本赛要 **18,533 genes 全基因**，且 D/E/F 是**匿名新背景、零目标背景扰动真值**。**「在同一背景里用 150 个监督扰动」不等于「在新背景里零样本」。**
2. **基因面板差 453 个基因。** 18,080 vs 18,533。这不是四舍五入，是**词表级不兼容**——用它必须先做面板映射，并接受映射带来的信息损失。
3. **它是六张卡里最「可动手」的一张**：有官方代码、有 MIT 许可、有 85M 小权重（本机 8 GiB 显存**可能**跑得动推理，但 flash-attention 编译在 WSL 下的可行性未验证）。
4. **它的定位是 raw-count decoder 候选，不是主效应模型。** 也就是说：**它回答「怎么生成 400 个合法计数细胞」，不回答「扰动后表达该是多少」。** 这两件事在 [第 03 课](../03-State上手.md) 与 [第 06 课](../06-其余路线全景.md) 里被明确分开。

**这张卡对本项目的实际用途**：**这是本课唯一给出「可能真能跑」的生成式候选。** 具体到比赛，它的价值在 **[第 03 课](../03-State上手.md) 的计数生成环节**：当 B1/B3 给出了群体层面的 $\mu$，需要把它变成 400 个整数计数细胞时，一个已发布的 85M 离散扩散模型是一个**比从零写 emitter 更有依据**的起点。**但必须先验证两件事**：(a) 面板能否从 18,080 映射到 18,533 而不破坏词表；(b) 本机能否编译 flash-attention。

**一处必须说清的配置张力。** `[S3]` 推理配置 `configs/infer/legacy_vcc.yaml` 里 `patch_size=32`，而训练主线的模型配置 `configs/modules/models/patch_dense.yaml` 里 `patch_size=8` 并注明「改变它会影响 patchify/depatchify 数据流与 checkpoint 兼容性」。同时 `use_gene_embedding_in_condition/fusion` 在 legacy 推理配置里是 `true`，在训练主线里是 `false`。**这不是笔误，是两套配置路径**——仓库里也确实存在 `src/compat/legacy_checkpoints.py`。**引用 Lingshu 的参数时，必须说明引用的是哪一套配置**，否则会拼出一个不存在的模型。

## 2. 诊断题

### 2.1 题一：仓库空的、论文说得好，算不算证据

> 卡 3（C3TL）的论文报告「与 State 相近或更好，训练 epoch 快 30 倍、显存 2.1 GB」，作者仓库 MIT 但只有 README、LICENSE 和 `.gitignore`。你是否应该把 C3TL 列为备选架构？

**答案：可以列为「备选架构」，但不能列为「性能证据」。**

两件事要分开：

| | 备选架构 | 性能证据 |
|---|---|---|
| 依据 | 论文描述的**结构与做法** | 需要能复核的实现或至少完整的数字口径 |
| C3TL 是否满足 | **满足**——「扰动编码与背景编码分离后组合」是可独立复现的架构想法 | **不满足**——无代码、无参数量、无训练墙钟时间；「快 30 倍」的基准是什么也没说 |

**更关键的第二个问题**：它的性能数字对本赛**根本不适用**（`[P3]` 目标背景用了 8%+2% 真实扰动）。所以即使代码齐全、数字可复核，**它证明的也不是零样本能力**。

**这道题在教你**：`INDEX.md` 里的「备选」和「采用」不是按论文好看程度分的，是按**它能回答哪个问题**分的。C3TL 能回答「分解结构长什么样」，不能回答「本赛该选谁」。

### 2.2 题二：两个模型都栽在同一处，说明了什么

> 卡 6（AlphaCell）明确「使用离散的已学习 perturbation ID，不能预测训练中未见的靶点」；[第 06 课](../06-其余路线全景.md) §4.3 诊断出 scGPT 的 `pert_encoder` 是 `nn.Embedding(3, d_model)`、扰动身份完全依赖靶基因在序列中的位置与表达值，因此**靶点表达为零时不可区分**。这两个失败模式是同一个吗？

**答案：是同一类，都是「靶点身份被编码成了不可外推的形式」。**

| | AlphaCell | scGPT（[第 06 课](../06-其余路线全景.md)） |
|---|---|---|
| 靶点身份存在哪 | **离散 ID 嵌入表**（每个训练中见过的靶点一个向量） | **基因序列中的位置 + 表达值** + 3 元 `pert_encoder` |
| 未见靶点会怎样 | **表里查不到，向量不存在** | 位置在，但若该靶点表达为零，模型只看到「零值 + 标记 1」 |
| 病根 | 身份参数**只对已见靶点定义** | 身份**依赖于一个可能为零的观测值** |

两者都不是「容量不够」，而是**接口把靶点身份绑在了不可外推的对象上**。加大模型、加数据都不能修。

**这道题在教你**：看到一个「零样本」宣称时，先问一句——**靶点身份在模型里是以什么形式存在的？** 如果是查找表、离散 ID、或依赖靶点自身的表达值，那么零样本是名义上的，不是结构上的。

**推论**：这也是 [第 06 课](../06-其余路线全景.md) §3.3 里 B3 的 `b_t` **若只是 ID embedding 就无法外推**的同一条理由。**三条独立路线（B3 / scGPT / AlphaCell）共用同一个陷阱**，这是本赛架构设计最值得设防的一处。

### 2.3 题三：面板差异是不是小事

> 卡 5（Lingshu-Cell）词表 18,080 genes，卡 6（AlphaCell）输出 19,253 genes，本赛要求 18,533 genes。这 453 与 720 的差，是「补几个零」就能解决的吗？

**答案：不是。面板差异是**词表映射问题**，不是**长度补齐问题**。**

三件事会同时发生：

1. **该有的基因为零 / 该为零的基因有值。** 模型词表里没有的 453 个基因，你**无法从模型里拿到它们的预测**；你只能填 0、填该背景下其他基因的均值、或从别处搬。**每一种填法都是一次未经验证的假设。**
2. **顺序不能靠位置对齐。** 基因 ID 必须按 **Ensembl ID / 符号**做集合运算，不能按列号切。这一点 [L0-01](../01-数据合同与首个基线.md) 已把 18,533 的符号对齐列为数据合同的一部分。
3. **词表变小会改变模型行为，不只是输出变短。** 卡 5 的 `patch_size` 会把基因**打包成 patch**；词表长度一变，打包的边界就变，**patch 内的基因组合与训练时不同**——这是结构级的扰动，不是后处理能修的。

**正确的做法**：先做一次**面板交集审计**，把「模型词表 ∩ 比赛面板」与两侧的差集都列出来，再决定是补、是弃、还是换模型。**这个审计是纯 CPU 的，几行集合运算，成本几乎为零——但它必须发生在训练之前。**

**这道题在教你**：跨模型复用资产时，**第一个要核对的是接口（词表/面板/基因顺序），不是指标。** 本课六张卡里有四张的面板互不相同（18,080 / 18,533 / 19,253 / 2,000 HVG），这个事实本身就说明：**「哪个模型更好」这个问题在本赛上无法脱离面板对齐来问。**
