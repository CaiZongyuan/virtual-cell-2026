## 0. 为什么按“证据门”排课

现在我们已经知道任务是什么，也能读懂 A、B、C 的 NTC 控制数据。接下来最容易犯的错误，是直接跳到 STATE、GEARS、扩散模型或单细胞基础模型，然后用一个总分判断模型好坏。

问题在于，一个提交失败可能来自完全不同的层次：

- 基因列错位，模型内容还没进入评分就已经失真；
- 背景表达保留得不错，但所有目标都得到同一个结果；
- 扰动方向正确，幅度却缩小到几乎看不见；
- 伪批量均值正确，却没有生成合理的单细胞差异；
- 验证划分泄漏了同一背景，离线成绩看起来很好，真正的新背景却失效；
- 深度模型确实更复杂，但没有比统计基线增加可测量的信息。

因此，每一课都回答一个可以被实验推翻的问题。只有通过当前证据门，增加模型复杂度才有意义。

## 2. 每一课都用同一套学习结构

后续课程不再把很多概念压进一篇超长说明。每课只讲透一个主要因果单元，并按下面的顺序展开：

1. **直觉解释**：先回答“为什么需要它”，不先抛公式；
2. **生物机制或数学对象**：解释量从哪里来、代表什么、不能代表什么；
3. **实验与数据流程**：逐步说明输入、实际操作、输出，以及每一步解决的问题；
4. **失败与噪声**：指出批次、测量、抽样、映射和实现会怎样制造假象；
5. **与 VC2026 的关系**：把知识落到 A–F、300 个目标、400 个细胞和六项指标；
6. **对模型的影响**：明确这个知识会改变哪个接口、特征、损失或验证方法；
7. **可复现实践**：产出脚本、表格或图，而不是只读概念；
8. **一道诊断题**：检查是否真的理解当前因果链。

软件类比只用于建立直觉。例如可以把数据合同类比为 API contract，把最终轮类比为生产发布；但细胞状态不是固定配置，生物测量也不是确定性日志。每次类比都必须紧邻写出边界。

## 3. 三条贯穿全程的成绩线

以后不再只保存一个总分。每次实验至少同时记录三条线：

### 3.1 生物效应线

目标基因是否下降？下游基因变化的方向和幅度是否合理？显著响应集合是否恢复？这一条主要连接差异表达和 delta 指标。官方六项指标会排除当前被扰动目标基因，因此“目标自身是否下降”只作内部生物 QC，不能直接抬高六项分数。

### 3.2 群体分布线

400 个细胞的总 UMI、检测基因数、方差、零比例、状态组成和基因间协同是否像真实群体？这一条防止把一个漂亮的伪批量向量冒充完整单细胞预测。

### 3.3 工程合同线

基因顺序、目标集合、context、计数类型、行数、稀疏项、内存、运行时间和随机种子是否正确？这一条不证明生物预测好，但任何一项失败都可能让好模型无法被正确评分。

## 4. 当前边界

- **已验证事实**：比赛结构、A–F 发布方式、每轮规模、原始计数合同和六项参考缩放指标来自官方保存页面。[S1][S2]
- **已有数据证据**：A/B/C NTC 的合同、逐细胞 QC 和 guide 级伪批量 PCA 已由上一课的真实数据审计得到。
- **工程路线**：七课顺序、证据门和模型梯子是本项目设计，不是 Arc 官方推荐方案。
- **待验证猜想**：跨背景 delta、集合表示、蛋白嵌入、计数生成器和神经模型是否能提高比赛分数，都必须通过后续公开真值与排行榜验证。
