**工程解释：**模型内部可使用归一化或对数表达，但提交的 `X` 必须恢复为符合合同的原始计数。密集形状有 6,671,880,000 个位置，本身就超过存储项上限；应分块生成、保存 CSR，并调用 `eliminate_zeros()` 清除显式零。不要把压缩文件体积当作矩阵密度合规证据。[Data](https://virtualcellchallenge.org/datasets)；[FAQ：density limit](https://virtualcellchallenge.org/faq)

## 4. 模型与数据使用边界

官方允许使用有权使用的公共或专有数据训练/微调模型，但 Rules 要求预测由一个或多个机器学习模型生成：

> “your predictions must be generated solely by one or more machine learning models you use”
>
> “you may not submit experimental laboratory results or results published in scientific literature in any part of your entry, nor use such results to revise predictions generated by a machine learning model”

因此正式方案应由拟合得到的模型及固定推理流程输出，不应把已测扰动结果或论文数值直接复制为答案、手工修补答案。原样复制 NTC 的 null baseline 可作为本地格式/评分 sanity check；**其正式参赛资格不在本次核验中确认**，不要仅因 `vcc prep` 通过就认为满足参赛方法要求。规则同时要求方法说明披露经典统计、机制或其他非学习组件，说明实现层面还需如实记录这些组件。[Rules：Machine Learning Predictions Only](https://virtualcellchallenge.org/rules#submitting-final-entries)；[Rules：method description](https://virtualcellchallenge.org/rules#finalists-winners-prizes)

当前 FAQ 的 [“Can I use Arc's State and/or Stack model in the Challenge?”](https://virtualcellchallenge.org/faq#legal) 已将 **State 与 Stack 并列说明**：任何参赛者为本比赛使用其代码被视为 Non-Commercial Purpose，但仍须遵守适用代码许可证；非商业参赛者可以使用预训练检查点，商业参赛者应申请相应商业许可，获批后可包含 90 天试用。不能继续把较旧方案中“Stack 一律需要单独书面比赛许可”的表述当作当前统一结论。本次仅核实官方比赛 FAQ 的表述，没有逐个 checkpoint 审计许可证。[FAQ](https://virtualcellchallenge.org/faq)；[State code license](https://github.com/ArcInstitute/state/blob/main/LICENSE)；[Stack code license](https://github.com/ArcInstitute/stack/blob/main/LICENSE)

该 FAQ 的关键原文是 “Any entrant may use Arc's State and/or Stack model code in order to participate in the Challenge (and such use will be considered a Non-Commercial Purpose solely to the extent of your use for participation in the Challenge), provided that you comply in all respects with all terms, conditions or restrictions in the applicable code license for State and/or Stack.” 对预训练检查点则另述 “you may use them if you are a non-commercial entrant”，并说明商业参赛者需申请商业许可。两者不能混为一种授权。

## 5. 评分：已确认的共同结论与一项实现前核对点

当前官网确认使用 `cell-eval2` 的 `vcc2026` profile，六项指标为 `pds`、`mse`、`nmae`、`fid`、`reach`、`jac`。先根据每个细胞背景中的实测均值与重复实验参考点缩放，再对六项及三个背景无权重平均；1 不是百分比或总分上限。靶基因自身的表达从六项指标中排除，因此只做靶基因敲低不能解决比赛要求的下游反应预测。[Evaluation：scoring](https://virtualcellchallenge.org/evaluation#scoring)；[FAQ：scoring](https://virtualcellchallenge.org/faq)

本次发现当前官方两个网页对**缩放 MSE 的下界**的说明详略不同：

- Evaluation 写 MSE “bounded at both ends, on 0 to 1”。
- FAQ 与本地旧译文一致，强调 MSE 上限 1、NMAE 下限 −6，且四项无截断下界，但没有在该段明确写出 MSE 下限 0。不能从这项省略推导 MSE 无下界。

当前 Evaluation 明确给出 `[0,1]` 的 MSE 缩放范围，优先于对 FAQ 省略内容的推测。本次未扩展到评分源代码版本审计，**不把网页说明等同于已检验实际部署代码**。模型实现应锁定官方 `cell-eval2` 版本、rule version 与具体配置，再核对 clipping/scaling；首提方案可依赖两页一致的“六项缩放等权平均”。[Evaluation](https://virtualcellchallenge.org/evaluation#scoring)；[FAQ](https://virtualcellchallenge.org/faq)；[official evaluator](https://github.com/ArcInstitute/cell-eval2)

## 6. 本地预检、打包与上传命令

以下命令来自在线 CLI reference，**本次未执行上传**。文件名是流程示例；使用当轮下载包内的基因与靶点清单。

```bash
# A/B/C：先检查，再打包。
vcc prep prediction.h5ad -g gene_names.csv --perts pert_counts.csv \
  --contexts A,B,C --dry-run
vcc prep prediction.h5ad -g gene_names.csv --perts pert_counts.csv \
  --contexts A,B,C -o prediction.vcc

# 仅在准备正式提交时执行；该命令会上传并启动评分。
vcc submit prediction.vcc --model-name model-v1 --wait
```

最终轮将 `--contexts` 改为 `D,E,F` 并使用最终轮清单。截至本次在线核验，CLI reference 的 `vcc prep --contexts` 默认仍是 `A,B,C`。CLI 的通用 `--max-cell-dim` 默认 400,000 不是赛题允许 400,000 行；实际必须满足每靶点每背景 400 行的更严格合同。保留 `--verify-targets`、`--check-cell-counts`、`--require-counts` 和 `--reject-controls` 默认检查。[CLI：prep](https://vcc-cli-wiki.virtualcellchallenge.org/cli-reference#vcc-prep)

`vcc submit` 接受 `.vcc`，也支持在给定基因/靶点清单后自动打包 `.h5ad`；`--model-name` 必填。推荐事先完成 `prep --dry-run` 与正式打包，方便检查最终文件和保存校验和。[CLI：submit](https://vcc-cli-wiki.virtualcellchallenge.org/cli-reference#vcc-submit)
