# 公开预训练权重微调：数据与本地比较方案

> 2026-09-25 用户重新确定方向。本文替代“尽快首次提交”的执行优先级；首轮结果与失败实现保留用于复核。**当前暂停全部官方提交**，后续由用户明确恢复。阶段按验收产物推进，不做时间估计。

## 1. 固定边界

- 主线是复用文献公开、许可适用的预训练权重进行微调，不从零预训练基础模型。小型新增适配层可以初始化训练；它们的范围、参数量与必要性必须单独记录。
- 首批比较 State 与 Stack；用同一批数据、固定划分和评价协议判断收益。先检查各模型微调前的原生行为，再测试冻结适配、有限解冻等变体。
- NTC 重采样和简单统计/线性方法保留为便宜的评价参照，不因此把主线改成从零训练大模型。
- 本地验证包含开发机和已授权的局域网服务器，只用空闲资源；环境使用 uv 和清华镜像，训练可视化使用 SwanLab。
- 未来恢复官方提交时，公开模型名自动生成为 `entry-<随机十六进制>`，不包含 State、Stack 或其他架构提示；内部保存公开名、父权重、代码版本、数据版本、checkpoint 与预测文件哈希的对应关系，并保留应有来源与许可说明。

四份 scPerturb 文件合计 **2,693,350 行**，这是下载到的原始记录数，含对照，不是最终质量合格的训练细胞数。上一轮仅准备了 276,447 行（含对照），使用 693-target 面板、每个源/靶点最多 256 个扰动细胞。因此当前不只是“缺数据”：还需检查已有数据如何选靶点、分配抽样量，以及是否丢失了有价值的基因和弱覆盖条件。

数据扩充按信息缺口排序：

1. **整理现有资产。** 从完整文件统计背景、靶点、guide、技术批次、NTC 数量、有效细胞数和测量基因；保留全量目录，训练子集由版本化协议产生。先看样本量学习曲线，再决定是否放宽旧 256-cell 上限。
2. **核查原作者全基因版本。** 现有压缩整理矩阵只有约 8k–10k 个基因，四来源在比赛轴上仅覆盖 10,480/18,533。优先对照 Replogle/Nadig 作者文件的基因元数据、计数层和版本；若原件增加所需测量基因，再下载相应文件，避免重复保存无信息增益的同源副本。
3. **补 Jurkat。** 已有明确的 Nadig/scPerturb 入口，服务器尚无该文件。先把它作为第二个整背景验证候选；使用 `zeroshot/jurkat` 父权重时同时核对作者留出协议。不要一边用于微调、一边称其为未见背景。后续根据训练/确认集分配决定是否纳入训练。
4. **再补不同生物背景。** 从既有清单的 Orion HCT116/HEK293T、Jiang 多细胞系等候选中选择；先核实 CRISPRi/KO 模态、原始计数、对照、许可及实际靶点覆盖，再按需下载或流式取子集。KO、药物与 CRISPRi 有不同干预机制，不能无标识混合训练。

“收集够”的标准是覆盖矩阵和明确的数据缺口：每个评测靶点是否有外部背景监督、每背景的对照/扰动是否足量、哪些基因实测、哪些只能外推，而不是凑到某个 GB 数或细胞总数。来源入口和模态边界复用 [扰动数据清单](perturbation-dataset-catalog.md)；同一原始实验的多个镜像或整理版只计一份证据。

## 3. VC2025 可以本地测，但需要选对协议

服务器已经保存 **15,482,497,461 bytes 的完整 H1 training 文件**、H1 对照、固定 benchmark 参考缓存以及三组首轮评分；H1 完整评测已经执行成功，无需重建评分器。开发机 `references/cell-eval2/docs/data/H1-VCC-2025-training.h5ad` 则只是 **600 × 1,000** 的教程示例，不能代替完整评价。

主要开发协议继续使用 [H1 benchmark v0.2.0](https://github.com/forrestsheldon/vcc2026-h1-benchmark/tree/d28dd0496cc9fbf1d0088ce171208c0deb54a268)：**126 targets × 400 cells，18,080 genes，VC2026 六指标**。它来自公开的 VC2025 H1 training 数据，是本地开发集，不是官方隐藏测试，也不是重现 VC2025 排行榜的原三指标。

两种验证必须分别命名：

| 协议 | 可用于训练的信息 | 能说明什么 |
|---|---|---|
| 同背景、留靶点（VC2025 式辅助检查） | H1 的另一组扰动训练标签 | 模型能否在已知 H1 背景预测未见靶点；不能证明 VC2026 新背景能力 |
| 整背景留出（主要协议） | 其他背景的扰动标签；推理只给 H1 NTC 和靶点 | 与 VC2026 的输入条件更接近；微调和 Stack 的示例检索均不能访问 H1 扰动真值 |

H1 已用于诊断和后续选模，应称开发背景。配置选定后另用完整留出的背景确认。每个模型分别记录父权重的预训练暴露：**微调没见过不等于预训练没见过**；没有可核对的训练清单时标为暴露未知，不夸称严格零样本。用过 H1 监督的公开 checkpoint 可以跑 H1 实验，但不能进入严格“未见 H1 背景”的主比较。

## 4. 首批模型：State + Stack

### State：先复现原生行为，再微调

已有官方 ST-HVG-Replogle 权重和运行环境。当前父 checkpoint 的基因轴、靶点词表、batch 编码与预处理都属于权重合同；原词表不覆盖比赛 300 个靶点，不能把旧适配失败归结为 State 所有权重无效。

下一轮先用父权重实际支持的来源/靶点/基因面板验证加载、尺度和无扰动校准。若所需原始基因或父预处理尚不明确，先补数据或追溯源码。原生行为确认后逐项接入新靶点和输出范围，比较适配前后，而不再次同时替换多个接口。旧全基因适配作为负结果保留，不能沿用为默认可靠起点。[首轮复盘](state-first-run-postmortem-2026-09-25.md)

### Stack：公开权重和微调入口都存在，可以实测

本次复核官方代码 commit `cacc2e4b09435c3e536d46237d10b50f222dd144`、两份 HF 模型元数据和模型卡：

| 资产 | 固定版本 | checkpoint 文件大小 | 当前状态 |
|---|---|---:|---|
| [Stack-Large](https://huggingface.co/arcinstitute/Stack-Large) | `6e1f352e8cc7f8718c74fe1d20b95c42e0942d9b` | 2,610,004,146 bytes | 元数据与 SHA 已登记，未下载/运行 |
| [Stack-Large-Aligned](https://huggingface.co/arcinstitute/Stack-Large-Aligned) | `b09f085dac03d170b078a5c72f550ae93686e544` | 2,613,863,242 bytes | 元数据与 SHA 已登记，未下载/运行 |

模型卡均标为 217M 参数、预训练来源约 150M scBaseCount 细胞；Aligned 另使用 CellxGene 45M 与 Parse 10M PBMC 做对齐。官方 `stack-finetune` 支持从 checkpoint 开始、使用冻结教师微调，所以可以沿用现成权重。**这个入口主要是原生上下文对齐流程，不自动等同于已验证的 CRISPRi 靶点监督训练方案。**

Stack 的条件通常由示例细胞提供，即上下文学习（in-context learning）：模型在推理时参考一组已知条件的细胞。拟测试的输入是“其他背景中某个靶点的扰动示例 + 目标背景的 NTC”；目标背景的扰动真值只交给评分器。没有外部同靶点示例的条件单独统计覆盖，不能借用验证真值填补。

第一组比较使用 **Aligned 原生推理 vs 同一 Aligned 权重的微调版本**。若其原生微调入口实际要求 Large 作为固定教师，则同时登记并固定教师 revision；教师提供信号不算从零预训练。微调前后固定示例检索、细胞窗口、种子和解码方法，使差异可解释。

源码具有负二项计数分布的均值、离散度与采样路径；不能笼统说它只输出归一化表达。但哪些输入层是 raw counts、基因筛选后的总计数如何使用、15,012 原生基因怎样对应目标完整轴，仍须在实际 checkpoint 上核实。先保持原生轴做小诊断，之后用独立验证过的计数/基因适配生成完整 H1 输出；子面板分数不冒充完整 benchmark。

24 GB GPU 上先测小 batch、较短细胞窗口的前向/反向与峰值，再决定可解冻范围。官方测试环境为 H100 80 GB，不能据 2.6 GB 文件大小推断训练显存足够。缩短窗口会改变示例信息量，应作为实验条件记录。日志接 SwanLab，不沿用官方默认 TensorBoard/W&B。

两种模型的原生预处理可以不同，但输入原始数据、训练/验证划分、输出合同与评分器保持一致。其他有公开权重的方法可追加登记；例如 Lingshu-Cell 的 H1 权重已有同背景监督暴露，不能无条件加入未见 H1 的比较。每个新增模型先通过资产、任务和校准检查，再占用完整训练资源。

## 5. 执行阶段与完成判据

| 阶段 | 交付物 | 进入下一阶段的条件 |
|---|---|---|
| A 数据与父权重盘点 | 文件版本/哈希、背景×靶点×细胞数矩阵、基因 mask、去重与预训练暴露表 | 有可复核的训练/开发/确认划分；已知缺口写清 |
| B 原生小规模运行 | State/Stack 各自原生推理、无扰动校准、gene/count 合同与资源记录 | 能复现原生接口；对照分布漂移没有明显超出对照抽样波动 |
| C 微调对照 | 同一父权重的未微调、冻结适配、有限解冻结果与 SwanLab 曲线 | 小型诊断优于或至少不劣于保守基线；一次只改变一个主要因素 |
| D 本地完整评价 | H1 六指标、原始 MSE/NMAE、逐靶点/覆盖分组、多种子结果 | 改善不是某一指标截断或一两个靶点驱动；再用另一个留出背景确认 |
| E 后续模型与数据增量 | 新候选/新增数据的受控比较 | 有明确新增信息及前述通过记录，不盲目扩大搜索 |
| 官方提交 | **暂停** | 用户明确恢复后再执行；本地分数变好不自动触发上传 |

模型比较保留 NTC、简单基线和负结果。不同参数量模型不把相同步数称为同等计算量；记录可训练参数、有效细胞/集合数和实际资源消耗。数据版本、父权重、预处理、基因映射、训练划分、检索示例、采样种子和计数解码都是实验身份的一部分。
